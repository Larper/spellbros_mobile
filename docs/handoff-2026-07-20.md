## 1. Task / goal

**Spellbros Mobile** is a mobile (portrait-landscape, touch-only) endless
runner-platformer built in **Godot 4.7**, written code-first: there is a single
scene (`scenes/main.tscn`) and every node is constructed in GDScript, with all
art drawn procedurally in `_draw()` calls (flat geometric shapes, no image
assets). The player is an auto-running wizard; the two verbs are **jump** (tap
left of the wizard) and **build a crumbling platform for 1 mana** (tap right of
the wizard).

The current work is the **level ladder**: seven themed 300-meter bands stacked on
top of the original endless-difficulty-phase generator, each band owning one
mechanical twist. The active effort is **playtest-driven tuning** — the human
(Neven) plays a build, reports what felt bad, and the AI implements fixes one
commit at a time. This session was a ten-item playtest round covering powerups,
three level reworks, two level-boundary transitions, and a darkness overhaul.

being clever.

- **Never launch the game window to verify.** Neven playtests himself. The AI
  verifies logic through the headless smoke suite only. Do not open the game to
  "check" a change.
- **One commit per feature, and never push.** Each self-contained feature gets
  its own commit with a descriptive body. The AI does not run `git push` —
  Neven pushes from his own terminal when he is ready. (He pushed this session's
  eight commits himself.)
- **Every gameplay change needs matching smoke-test coverage** in
  `tests/smoke_test.gd`, and the suite must print `SMOKE RESULT: PASS
  (0 failures)` before committing.
- **Report outcomes plainly.** State what was verified and what was not. He reads
  the summary, not the diff.
- **Design intent comes from him; ask nothing, implement the intent.** When his
  description of a level conflicts with what the code does, his description wins
  — rewrite the generator rather than tuning numbers around the old shape. Two
  levels (SPRINGS, BLOB BRIDGES) were fully regenerated this way, not tweaked.
- **Comments explain constraints, not narration.** The codebase comments heavily
  on *why* a constant has its value (usually jump math or a playtest note),
  never on what the next line does.
- **Level bands need gentle hand-offs on BOTH edges** — a teach-in entering and a
  wind-down leaving. This is a standing rule he arrived at after dying twice at
  hard-cut boundaries. See gotchas below.

## 7. Commands

### Headless logic test — the primary verification tool

```powershell
godot --headless --path . -s res://tests/smoke_test.gd
```

**Gotcha (cost real time this session):** run directly in PowerShell, this
prints only the Godot banner — the script's `print()` output does not reach the
PowerShell pipeline. To actually read results:

```powershell
cmd /c "godot --headless --path . -s res://tests/smoke_test.gd 2>&1" | Select-String "RESULT"
```

Use `Select-Object -Last 50` instead of `Select-String` to see the full band
audit table. Exit code is `0` on pass, `1` on failure, and is reliable either way.

### After adding a new `class_name` script

```powershell
godot --headless --path . --import
```

Skipping this makes the new class name fail to resolve at runtime — this was
needed when `ShieldPickup` was added.

### Windowed launch (Neven only; the AI must not do this)

Must use `Start-Process`, because `godot.exe` is a GUI-subsystem binary that
returns immediately otherwise and gets killed by job cleanup.

### Web export + deploy

```powershell
powershell -File deploy.ps1            # export + upload + verify
powershell -File deploy.ps1 -SkipExport # reuse build/web as-is
```

Export alone:
`godot --headless --path . --export-release "Web" build/web/index.html`
(`build/` is gitignored; the Web preset is single-threaded so it runs on a
static host without COOP/COEP headers). The script verifies the live site by
byte-matching `index.wasm` and throws on mismatch.

### Committing

`git commit -m` with a PowerShell here-string **broke** this session when the
message contained embedded quote characters — PowerShell split the message and
git reported bogus `pathspec` errors. Robust pattern: write the message to a
scratch file and use

```powershell
git commit -F <path-to-message-file>
```

Commit messages end with:
`Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`

## 8. Design decisions & gotchas

### The jump math — load-bearing for every gap constant

`Player.GRAVITY = 3300`, `Player.JUMP_VELOCITY = -1170`. Everything below is
derived and is quoted in comments throughout `terrain_spawner.gd`:

- Full-jump airtime back to takeoff height: `2*1170/3300 = 0.709 s`
  → **flat horizontal reach = `0.709 * v`** at run speed `v`.
- Max jump height: `1170² / (2*3300) = 207 px`.
- Landing `R` px **higher** shortens the arc:
  `t = (1170 + sqrt(1170² - 6600R)) / 3300`, so reach = `t * v`.
- `SPRING_LAUNCH = -1500` → rise `1500²/6600 = 341 px`.
- `STOMP_BOUNCE = -1000` → rise `152 px`; bounce-to-apex takes `0.303 s`.
- **One built platform bridges `1.418*v + 240 px`** (jump + 240 px deck + jump).

**Normal gaps are sized as fractions of the LIVE run speed**, never as absolute
pixels, so they stay jumpable across the whole 470→900 px/s speed ramp. This is
why the constants are named `*_FRAC`. If you add a generator, size gaps this way
or the level breaks at speed cap.

### Difficulty gates on chunk position, not player position

`_spawn_chunk()` computes `d` from `next_x`, i.e. **where the chunk will be**,
because chunks spawn ~27 m ahead of the player. Gating on `main.distance_m` made
every phase arrive visibly late. Do not "simplify" this.

### Level ladder

Seven bands, 300 m each: FOUNDATIONS 0, SPRINGS 300, BLOB BRIDGES 600,
FLIPSIDE 900, UMBRA 1200, SPELLBROS 1500, THE VOID 1800. `Levels.level_for(d)`
maps meters → index; the index constants (`Levels.SPRINGS` etc.) are used for
readable checks across the codebase.

Starting at a later level credits `start_offset_m` meters and seeds `2 + i` mana
so the twist is playable on arrival. Score is absolute meters wherever you start;
bests are tracked **per starting level** so late starts never beat a from-zero run.

### Boundary hand-offs — the standing rule

Neven died twice at hard cuts, so every band now needs **both**:

- a **teach-in** on entry (`TEACH_M = 45`, `_is_teach(d)`) — the mechanic in its
  gentlest form, no ambushes; and
- a **wind-down** on exit (`WIND_DOWN_M = 45`) — return to plain run-and-jump on
  continuous ground before the next band's chunks begin.

Additionally, bands whose twist **changes the controls** need an opening runway
(`RUNWAY_M = 20`): FLIPSIDE opens with a plain continuous floor where taps still
*jump*, giving ~2 s to read the banner before the first flip is demanded.

**Banners fire early, deliberately.** `Main._physics_process` announces
`Levels.level_for(distance_m + WIND_DOWN_M)`, tracked in `announced_level`
separately from `cur_level` (which still gates unlocks at the true boundary).
Announcing UMBRA *at* 1200 m was too late to prepare for. Likewise the UMBRA
darkness is a **gradient** in `psy_theme.gd`, ramping from 60 m before the band
and blooming back out over SPELLBROS' first 30 m — never a hard cut.

### Per-level generator notes

- **SPRINGS** (`_spawn_spring_chunk` / `_spawn_spring_void`) — was twice
  rewritten this session. Final shape: **deck sections** of 2–4 near-level
  pillars with plain jumpable gaps (free, no mana), separated by **void
  crossings** of `1.45–1.7 * v`. A crossing is deliberately too wide for one pad:
  the line is run off → pad → launch → **second pad at the apex** → launch →
  land the higher far deck. The 5-crystal trail is **sampled from that exact
  two-arc flight path**, so flying the intended line collects them naturally —
  if you change the launch constants, regenerate the trail math too.
  `spring_deck_left` counts down the current deck section.
- **BLOB BRIDGES** (`_spawn_bridge_chunk`) — three gap kinds keyed by `bkind`:
  `blob` (~62%), `plain` blob-free breather (~18%), `bmega` build-demanding
  (~20%), plus `out` for the wind-down. **The flow chain is the design goal**:
  all blobs sit at one shared stomp height (`deck_y - 90`), decks are narrow
  (210–290 px) and flat (±30 px drift), and doubles sit at 0.42/0.72 of the gap
  — one plain bounce apart. A stomp bounce plus the refreshed tap-jump fired at
  bounce apex covers ≈`1.0–1.1 * v` horizontally, enough to carry from a late
  blob across a deck onto the next gap's blob without touching down. **The deck
  width and blob height are chain-critical — do not widen decks casually.**
- **FLIPSIDE** (`_spawn_flip_chunk`) — alternating floor/ceiling strips sharing
  an overlap window `ov`; the tap becomes a gravity flip. Flips only execute
  from a surface or coyote window: a true mid-air flip is a disguised jump
  (flip up, flip back = free hop), so airborne taps are refused. The recovery
  tool for a bad flip is a **build** — pads are `solid` in this level and catch
  the wizard from either gravity. Dead zones (both surfaces gone) are banned
  near the wind-down.
- **UMBRA** — the twist is **sight as a resource**. Ambient modulate is 0.03
  (near-total black), the wizard's own halo is only 300 px, and lantern
  platforms carry a brighter 420 px light. Building ahead is how you see the
  route. Crystals are `lit` here and beacon through the dark.
- **SPELLBROS** — the echo brother mirrors the player through the camera's
  horizontal center line, banks crystals by proximity (physics can't see him),
  **and guards**: `try_guard()` intercepts one otherwise-lethal blob touch, then
  goes ghost-faint for `GUARD_COOLDOWN = 10 s`. His alpha is the readout.
- **THE VOID** (from `PHASE_VOID = 1800`) — mostly open sky; fragment trails
  must be caught with well-placed platforms.

### Intercept order on a lethal blob touch

In `SpikeBlob._lethal()`: **echo-bro guard first** (it recharges on its own),
**then the purple shield** (a held consumable), then death. Order matters — you
do not want a limited consumable spent while a free recharging guard was ready.

### Stomps: aim forgiveness, not timing forgiveness

An earlier iteration made *any* contact from above a stomp; blobs read as
trampolines. Current rule: direct contact requires **falling with feet above the
blob's midline**; side and rising touches kill. The forgiveness lives in
`SpikeBlob._stomp_assist()`, polled per frame — while falling, feet sweeping the
band around the blob's crown within `ASSIST_HALF_W = 95 px` (vs ~60 px natural
contact width) still squishes. This targets the real complaint: a slight
horizontal miss used to mean falling into the gap.

### Entity budget

Max 2 entities (crystals + enemies + pickups) per chunk, 3 after `PHASE_RICH`
(300 m), so mana stays scarce. **Exempt:** endgame void segments and SPRINGS
void crossings — their fragment trails *are* the economy, not clutter. The smoke
test encodes this exemption; if you add another trail-based generator, add it there.

### Camera

Zoom 1.25 (visible world 1536×864), wizard at ~22% from the left edge. The crush
camera never waits: it holds a lead but keeps rolling at 85% of run speed
(capped at `CAMERA_CHASE_CAP = 400 px/s`) if the player stalls; fall behind the
left edge and you die. The cap exists because at capped run speed the chase
would otherwise eat the reaction window before a missed stair jump could be
answered with a build. `camera_target_y()` eases down when terrain ahead sits
lower, reading static chunk data so it never pulses with the jump arc.

### Other traps

- `BUILD_TOUCH_NUDGE` is **0**. It used to be 90 px (compensating for thumbs
  landing right of the aim point); Neven zeroed it after phone testing. The
  smoke test asserts the nudge, so it stays honest either way.
- Blobs are **static circles**. They used to patrol and had spiky heads; Neven's
  call was that static enemies read far better at late-game speeds. `speed` is
  still on the class for spawner compatibility but is ignored.
- The HUD runs `PROCESS_MODE_ALWAYS` because it owns pausing.
- `Levels.save_path` is a `static var`, not a `const`, specifically so the test
  can point saves at a scratch file.
